# 校园助理 · School Assistant

给学生用的截止日期管家。作业、竞赛、考试、活动，凡是带时间的通知，截图或打一句话丢进来，它记成条目；想不起来还有什么没交，问一句「最近有什么要交的」。

课表也能截图导入，记事本顶部直接显示今天上什么课、在哪个教室。

**在线体验**：https://school-assistant.app.workbuddy.host/?sharecode=ENB4ABGI2J

## 它长什么样

两套主题，用户自己选，默认「元气糖果」：

| 元气糖果（默认） | 极光玻璃 |
|---|---|
| 明亮撞色、粗描边、硬阴影 | 深色底、流动极光、毛玻璃 |
| 白天用、亲和力拉满 | 夜里看、更安静 |

助理的名字、它对你的称呼、头像，全部可以改。默认名 **小助理**，默认称呼 **总裁**。

### 一套代码，两种形态

| 手机（<880px） | 电脑（≥880px） |
|---|---|
| 单列 App：顶栏 + 卡片流 + 底部标签栏 | 三栏工作台：左侧导航 / 中间内容 / 右侧常驻对话 |
| 底部输入框，点「对话」页签聊天 | 中间放 7 日周历格子，右边随时能聊 |
| 日期用紧凑圆点条 | 880–1199px 时周历自动退回圆点条，避免标题被压扁 |

断点是 `@media (min-width:880px)`。电脑上不会再出现"手机框摆在中间"的演示样子。

## 快速开始

不需要安装任何东西，也没有构建步骤。

```bash
git clone https://github.com/Czl4188/school-assistant.git
cd school-assistant
```

双击 `index.html` 就能跑。或者起个本地服务：

## 现在能干什么

**课表（识图导入）**

记事本顶部常驻一张「今日课程」卡片：今天几节课、几点上、在几号楼哪个房间。没课就写「今天没课」，一节课都没导入过会提示去导。

卡片右下角是「全部课表」——点开是周一到周日的完整课表，按天分组，认错的课可以一条条删掉。

导入方式：卡片右下角「全部课表」→「导入课表」，选图。**支持一次选多张**——很多学校的课程表和作息时间表是分开的两张图，一起选进来，本地按节次把时间对上。

模型对每张图都按同一种结构抽：

> `courses`：一行一节课，科目名称、日期、起止时间（或第几节）、楼号 + 房间号、备注（老师/单双周）。
> `periods`：作息表里的「第几节 → 几点」对照，比如「第1-2节 08:00-09:40」。

课程表那张图只有 `courses`，作息表那张只有 `periods`，两张图的结果在本地合并。所以：

- 只写「周一」的按每周重复记，写了「11月20日」这种具体日期的按一次性课程记
- 只写了「第1-2节」的课，等作息表到了再换算成具体时刻；作息表本来就是后选的也没关系，会回头重算
- 图里直接写了 `08:00-09:40` 的，不会被作息表改掉
- 没有作息表时退回内置的默认作息（第 1 节 08:00 起，每节 45 分钟）

时间格式认得很宽：`8:00-9:40`、`第1-2节`、`下午2点到4点`、`晚上7点` 都能换算。认不出时间就留空显示「待补」，不瞎填。

导入前会先弹一张确认面板，列出认到的课，点 × 去掉认错的，确认无误再「存进课表」。面板上还能「再加一张」——比如先拍课程表，发现没拍作息表，补一张进去，时间会自动补上。重复导入不会产生重复条目（同科目 + 同星期 + 同时间 + 同教室视为同一条）。

导入过的作息表会存在本地（`db.periods`），以后单独再导课程表也能直接用。

**识图录入（已接千问视觉模型）**

点输入框左边的相机图标：

- 手机上是「拍照 / 从相册选择」两个入口 —— 拍照会直接调起相机，相册可以选微信截图
- 电脑上是「选择一张图片」，也可以用 `Ctrl+V` 粘贴截图，或把图片拖进对话区

图片会先压到 1280px 再发给 `qwen3-vl-plus`，模型按下面的规则抽取：

> 一件事有多个时间（报名截止 / 初赛 / 提交）就拆成多条；只抽真正的时间节点，不抽"联系人""各班级"；看不出时间的也保留，标记「时间待补」。

识别完不会直接写进记事本，而是先弹一张确认卡，列出抽到的事项，点「写入记事本」才落库。

> ⚠️ **密钥安全**：`index.html` 里的 `QWEN.key` 是明文写在前端的，任何人打开网页都能在源码里看到。这是"打开即用"的代价。要长期对外，建议改成服务端代理并轮换密钥，见文末。

**对话（千问理解 + 本地兜底）**

每句话都先交给 `qwen-plus` 判断意图，输出一个 JSON：

| intent | 触发 | 处理 |
|---|---|---|
| `record` | 给了带时间的待办 | 抽取事项写入记事本，回执由本地按真实时间生成 |
| `query` | 问自己的事（最近有什么、这周几件） | 模型只读记事本快照，不许编 |
| `complete` | 「XX 做完了」 | 按快照编号划掉 |
| `weather` | 问天气 | 走 Open-Meteo 实时数据，不让模型编 |
| `chat` | 其它（问时间、问你是谁、闲聊） | 直接回答 |

几条硬规矩：

- **模型只判断和说话，不算时间。** 抽取出来的 `raw_time`（如「11月15日 23:59」）交给本地解析器换算，避免模型把日期算错一个月。
- **记账宁可不记。** 模型把「今天星期几」「你好」误判成待办时，本地有三道校验会拦下来，最多回一句「你是想记事情，还是在问我？」。
- **模型挂了也得能用。** 两次调用都失败就退回本地规则引擎，功能降级但不断线。
- 复杂句子（多意图、模糊表达）会自动用 `qwen-max` 重判一次。

**文字录入（本地规则解析）**
| 你说 | 它记成 |
|---|---|
| `11月15日 23:59 数学建模国赛报名` | 竞赛 · 11/15 23:59 |
| `明天晚上8点 交数据结构实验报告` | 作业 · 次日 20:00 |
| `下周五 英语演讲比赛初赛 14:30` | 竞赛 · 下周五 14:30 |
| `周三下午三点 组会` | 11/18 15:00（中文数字也认） |
| `3天后 社团招新材料截止` | 3 天后 23:59 |
| `这周要交物理实验报告` | 本周日 23:59 |

支持的写法：`11月15日` / `11/15` / `2026-11-15` / `今天` / `明天` / `后天` / `大后天` / `3天后` / `周三` / `下周五` / `这周` / `下午三点` / `晚上8点` / `14:30`。

抽不到时间不会瞎猜，会记成「时间待补」并追问一句。

**查询**

- 「最近有什么要交的」→ 先给最急那条，再列 3 条
- 「这周有几件事」→ 本周全部
- 「记事本」→ 按分组输出
- 「我做完了 XX」→ 划掉对应条目

**提醒分级**：3 天内报剩余天数，当天单独拎出来，逾期直接说"过了几天"。

## 数据与状态

- 存 `localStorage`，key 是 `campus-assistant-v1`
- 结构：`{ profile: {name, call, theme, avatar}, records: [...], courses: [...], chats: [...], seeded }`
- 一条记录：`{ id, title, due, kind, note, done, createdAt }`，`due` 是时间戳，可为 `null`（待补）
- 一条课程：`{ id, title, weekday, date, start, end, room, note, pf, pt }`
  - `weekday` 是 0–6（0 是周日），一定有，用来排周表
  - `date` 只在图里写了具体日期（`11月20日` / `2026-11-20`）时才有值，用来判断「当天课程」
  - `start` / `end` 是 `"08:00"` 这样的字符串，为空表示「待补」
  - `pf` / `pt` 起止节次（`第1-2节` → 1 / 2），只写了节次的课靠它跟作息表对时间
- 作息表：`periods: [{ n, start, end }]`，从「时间表」那张图抽出来，和课程分开存，重导课程表时不用再拍一次
- 首次打开会播种 4 条示例待办，方便直接看到效果（课表不播种，保持为空）

**调试用的 URL 参数**（不写入本地设置，适合分享特定状态）：

```
index.html#theme=aurora              切到极光主题
index.html#view=note                 直接打开记事本
index.html#sheet=1                   打开设置面板
index.html#edit=1                    打开第一条的编辑面板
```

## 想继续做，可以捡这些

按优先级大致排：

1. **把密钥挪到服务端** —— 现在 key 明文在前端，公开仓库 + 公开网页双重暴露。正确做法是加一个最小的转发函数（云函数 / Cloudflare Worker 都行），前端只打自己的域，key 放环境变量。
2. **提醒推送** —— 目前只有打开页面才看得到。需要 Service Worker + 通知权限，或者接一个后端定时任务。
3. **课表增强** —— 现在只认图片，还不能按周次过滤（单双周、1–16 周），也不支持手动加课和导出 `.ics`。内置的默认作息表（第 1 节 08:00 起）只是兜底，真用了「时间表」图之后以图里的为准。
4. **导出** —— 导出 `.ics` 到手机日历，是学生最想要的功能之一。
5. **多端同步** —— 现在数据只在本机，换设备就没了。
6. **更聪明的解析** —— 本地解析器还不支持中文月份（"十一月二十号"）、不支持"第十周周三"这种校历表达。走识图时这些交给模型，问题不大。

## 改代码要注意的

- **单文件、零依赖、零构建**，这是刻意的：任何人 clone 下来双击就能改，不用装 node。
- **主题是两套独立的 CSS 规则**，不是换变量。因为糖果和极光的结构差异太大（描边+硬阴影 vs 毛玻璃+渐变）。加新主题就在 CSS 里加一组 `[data-theme="xxx"]` 规则，再到设置面板加一张卡片。
- **手机版和电脑版是同一份 DOM**，靠 `@media (min-width:880px)` 切换。`.sidebar` / `.chatpane` 是桌面专属容器，手机端 `display:none`；对话内容由 `renderChat()` 同时写进 `#view-chat`（手机）和 `#chatPaneBody`（桌面）。改对话渲染时两个容器一起改，否则另一端会空。
- **别把 `.app` 写死成固定宽度**。手机是纵向 flex，电脑是 `grid-template-columns: 238px 1fr 390px`，靠断点切换，两种都在 `index.html` 顶部那段 CSS 里。
- **`--`开头的变量只有少数几个**，大部分数值直接写在规则里。改之前先搜一遍类名，避免互相覆盖。
- 头像有两种模式：字形（`type:"glyph"`）和上传图片（`type:"img"`，存 dataURL）。图片模式会让 localStorage 变大，注意 5MB 上限。
- 改动请开分支 + PR，别直接推 main。
